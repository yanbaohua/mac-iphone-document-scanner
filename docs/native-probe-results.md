# 原生静态照片探针结果

状态：已完成真机拍摄；Checkpoint A = **No-Go**。

验证日期：2026-10-09。

## 验证目标

- 设备发现只使用 `AVCaptureDevice.DeviceType.continuityCamera`，不回退到 Mac 内置摄像头。
- 从设备每个格式的 `supportedMaxPhotoDimensions` 选择总像素最大的合法尺寸。
- 保存 `AVCapturePhoto.fileDataRepresentation()` 返回的 HEIC/JPEG 数据，不经过缩放、插值、透视或二值化。

## 真机结果

| 项目 | 结果 |
| --- | --- |
| 设备类型 | `AVCaptureDeviceTypeContinuityCamera` |
| 设备全部报告尺寸 | 1920×1440、1920×1080、1280×720、640×480 |
| 会话提交后 | 视频 1920×1440，照片 1920×1440 |
| 会话实际启动后 | 视频 1920×1080，照片 1920×1080 |
| 请求尺寸 | 1920×1080（2,073,600 像素） |
| 实际输出尺寸 | 1920×1080（2,073,600 像素） |
| 编码与文件大小 | HEIC / HEVC Main，158,729 bytes（界面显示 159 KB） |
| 本机解码 | macOS “预览”可正常打开；`sips` 识别为 1920×1080 HEIC RGB |
| Python 基线 | 1920×1440（2,764,800 像素） |
| Checkpoint A 像素门槛 | 不少于 5,529,600 像素 |
| 同机位 10 磅文字细节 | 未继续：像素硬门槛已失败 |

## 结论

- 实际照片只有 Checkpoint A 像素门槛的 **37.5%**。
- 实际照片像素数只有 Python 1920×1440 基线的 **75%**，因此不存在“原生版已获得更多真实细节”的证据。
- 连续互通设备在会话启动前曾报告 1920×1440，但 `AVCaptureSession.startRunning()` 后实际协商为 1920×1080。应用按启动后的真实活动格式拍摄，没有做插值放大。
- 因为第一个硬门槛已失败，本轮不再要求用户进行 10 磅文字主观对比，也不进入 Task 4–8。

## 真机步骤

1. 连接 iPhone，保持解锁，关闭正在占用相机的其他应用。
2. 在应用中点击“连接 iPhone 相机”，核对日志的设备类型和尺寸。
3. 选择本机目录，固定机位与光线，拍摄包含 10 磅文字的同一页。
4. 用 Finder 的“显示简介”或图像检查工具核对真实像素尺寸。
5. 与 Python 版 1920×1440 样张并排100% 放大，核对笔画边缘和细小字符是否有真实额外细节。
